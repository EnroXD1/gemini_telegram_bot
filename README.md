# Telegram-бот с Gemini, OpenRouter и резервом Groq

**Текущая версия: 1.17.1**

Готовый асинхронный Telegram-бот, который умеет обращаться к Gemini напрямую
или через OpenRouter, а при исчерпании лимита выбранной модели — автоматически
переключаться между всеми настроенными API. Проект рассчитан на личные чаты, группы,
темы форумов и Telegram Business-сообщения. По умолчанию используется long
polling, поэтому домен и HTTPS-сертификат для первого запуска не нужны.

Актуальная конфигурация проекта на 16 августа 2026 года:

- Python 3.11+;
- aiogram 3.30+;
- официальный Google Gen AI SDK 2.11+;
- прямой Google API, OpenRouter или Groq, выбираемый через `.env` или командой
  владельца;
- модели `gemini-3.6-flash` для Google, динамический `openrouter/free` для OpenRouter
  и `openai/gpt-oss-20b` для Groq, а также настраиваемый пул бесплатных
  моделей OpenRouter и Groq;
- SQLite для настроек, ограниченной истории, Business-снимков и минимальной
  статистики использования.
- Pillow 12+ для безопасной локальной нарезки фотографий без обращения к AI.

## Версия 1.17.1

- Уточнена стандартная инструкция: LaTeX нужен не только для итогового ответа,
  но и для условия, подстановок, индукционного предположения и промежуточных
  преобразований. Продолжения также просят сохранять LaTeX. Собственный
  `GEMINI_SYSTEM_PROMPT` не заменяется; строгое соблюдение инструкции LLM не гарантировано.
- Отдельные строки, явно похожие на уравнения, получают математическое оформление,
  даже если модель забыла `$...$`. Unicode-степени, индексы и математические знаки
  преобразуются в LaTeX. Код, URL, цены, обычный текст и несбалансированные выражения
  не преобразуются. Значения и неоднозначные записи вроде `1/30n` не пересчитываются.
- При достижении лимита ответа завершённые формулы больше не теряют нативный
  рендеринг. Незакрытый математический фрагмент показывается читаемым текстом,
  без добавления недостающих скобок или членов выражения; предупреждение о лимите
  остаётся. Исходный ответ сохраняется в истории для последующего продолжения.
  Дополнительных AI-запросов или увеличения токенных лимитов не требуется.

### Версия 1.17.0

- Groq теперь обрабатывает фотографии через `GROQ_VISION_MODEL=qwen/qwen3.8-27b`.
  При выбранном Groq текст остаётся на `GROQ_MODEL`, а фото автоматически идут
  Vision-модели того же провайдера, без заведомо неудачной попытки GPT OSS.
  Достаточно существующего `GROQ_API_KEY` или `GROQ_API_KEYS`; новый ключ не нужен.
- Поддержаны до трёх JPEG/PNG/WebP за запрос, в том числе изображения-документы
  и фотографии из reply. PDF, аудио, видео, другие форматы и большие альбомы
  передаются прежним резервным провайдерам без потери частей запроса.
  Пустой `GROQ_VISION_MODEL=` отключает автоматический Vision-маршрут.
- Фото передаются внутри HTTPS-запроса, без загрузки на публичный файловый хостинг.
  Base64 формируется небольшими блоками, как для OpenRouter; новый SDK не нужен.
  Сохранены история, продолжения длинных ответов, ротация ключей и карантин
  после 429/503. Повторные запросы пропускают остывающую Vision-модель.
- Qwen с фото работает без отдельного thinking-бюджета (`reasoning_effort=none`),
  чтобы бесплатный лимит не уходил на скрытые рассуждения. Ответы всё равно могут
  содержать пошаговое решение и LaTeX; математическая правильность не гарантируется.
  В продолжениях текущего ответа изображения отправляются снова; в SQLite
  хранится только текстовая история, не base64 изображений.
- `/model`, выбор моделей и `/diagnostics` показывают Vision-маршрут отдельно.
  Строгий режим «Только бесплатно» по-прежнему исключает весь Groq: тариф аккаунта
  нельзя определить по ключу. Это не меняет тариф и биллинг в GroqCloud.
  См. [Groq Vision](https://console.groq.com/docs/vision) и
  [лимиты Groq](https://console.groq.com/docs/rate-limits).

  Собственный `GEMINI_SYSTEM_PROMPT` не перезаписывается.
- Если Telegram отклоняет Rich Message или не разрешает его для Business-аккаунта,
  отправляется читаемый Unicode-текст. При ошибке позднего блока уже доставленные
  блоки не повторяются; сетевые ошибки с неизвестным статусом доставки не скрываются

- `MATH_RENDER_MODE=auto` включён по умолчанию; `text` оставляет только текстовое
  преобразование. В inline-режиме формулы нормализуются в обычный текст без нового
  AI-запроса. Обычные ответы без формул сохраняют прежнее Markdown-оформление.
  Частичные ответы остаются обычным текстом, но завершённые формулы в них также
  преобразуются в читаемую запись; исходная история диалога не изменяется.

### Версия 1.14.0

- Добавлены необязательные пулы `GOOGLE_API_KEYS=key1,key2,key3` и
  `GROQ_API_KEYS=key1,key2,key3`. Для Google поддержан также `GEMINI_API_KEYS`.
  Старые `GEMINI_API_KEY` и `GROQ_API_KEY` работают без изменений, если список пуст.
  Повторы и пустые элементы исключаются, пробелы по краям убираются; предел —
  16 уникальных ключей провайдера.
- При `429` бот ставит пару «ключ + модель» на паузу и пробует следующий ключ
  по кругу для той же модели. Здоровый ключ остаётся текущим до следующего `429`.
  За запрос каждый ключ проверяется не больше одного раза. Действуют `Retry-After`
  или `AI_FALLBACK_COOLDOWN_SECONDS`; ожидание паузы не блокирует запрос.
- На резервный AI-маршрут бот переходит, когда доступные ключи не помогли.
  Если весь пул остывает, следующие запросы сразу пропускают этот маршрут.
  После паузы допускается одна проверка восстановления на ключ/модель.
  Отмена и поздний успех параллельного запроса не стирают новый карантин.
- `503` и сетевые сбои не запускают перебор ключей — ими по-прежнему управляет
  Circuit Breaker модели. `401/403` требуют проверки конфигурации, а не попыток
  обходить отказ другим ключом. Строгий бесплатный режим по-прежнему исключает
  Google/Groq независимо от количества ключей.
- В пуле Google используется `generateContent` с существующей ограниченной
  локальной историей: серверный Interaction ID не передаётся ключу другого
  проекта. С одним ключом сохранена прежняя цепочка Interactions/Vertex.
  Если квота исчерпана уже при продолжении ответа, готовый фрагмент сохраняется,
  ключ уходит на паузу, а следующий запрос использует другой доступный ключ.
- Groq использует один HTTP-клиент с отдельным Authorization на каждый запрос,
  без изменения общих заголовков при параллельной работе. Дополнительные клиенты
  Google создаются по необходимости, переиспользуются и закрываются при остановке;
  исходные вложения не копируются для каждого ключа.
- `/diagnostics` показывает количество доступных ключей, но не сами ключи и не
  их фрагменты. Секреты исключены из `repr(Settings)`, а ошибки Google/Groq
  журналируются без сырых SDK-traceback, способных содержать ключ. Значения
  ключей и их карантин не сохраняются в SQLite; новые таблицы не нужны.

### Версия 1.13.0

- Добавлен inline-режим `@bot_username запрос`: перевод (`tr en Привет` /
  `переведи на английский Привет`), исправление (`fix Текст` / `исправь Текст`),
  локальный калькулятор (`calc (15+5)*3`) и обычный вопрос AI. `/inline` открывает

- Результат сначала появляется в списке предпросмотра; только выбор результата
  пользователем отправляет его в чат. Нет автоматически публикуемых заглушек
  «Думаю…» и сообщений об ошибке. Для запуска нужен `/setinline` в BotFather;
  `/setinlinefeedback` и доступ к истории чужих чатов не требуются.
- Доступ проверяется по `from_user.id`: учитываются владельцы, баны и новый
  необязательный `INLINE_ALLOWED_USER_IDS`. По умолчанию разрешены все
  незаблокированные пользователи. `INLINE_ENABLED=false` отключает inline для всех.
  При ограниченных `ALLOWED_CHAT_IDS` нужны явно разрешённые пользовательские ID;
  добавление группы в старый список само по себе не открывает inline всем.
- Inline использует текущую AI-модель, бесплатный режим, резервную цепочку и
  Circuit Breaker, но не историю обычного диалога. Общий антиспам не позволяет
  одновременно запускать AI из лички и inline. Бан отменяет активную генерацию.
- Добавлены задержка ввода 0,8 секунды, отмена устаревших запросов и персональный
  кэш на 5 минут (до 128 записей, до 64 фоновых заданий). Повтор одного запроса
  не запускает вторую генерацию; смена модели/бесплатного режима меняет ключ кэша.
  В Telegram всегда передаются `is_personal=true`, `cache_time=0`.
- Inline-AI ограничен 7 секундами ожидания, чтобы не держать поиск дольше срока
  жизни запроса. Медленная модель может не успеть: в этом случае предлагается
  повторить запрос или открыть личку. Успешные ответы ограничены 3800 UTF-16
  единицами и отправляются как обычный текст, без HTML/Markdown и предпросмотра ссылок.
- Калькулятор работает без AI и без `eval`: только ограниченная арифметика,
  скобки и десятичные числа. Вызовы функций, доступ к файлам, чрезмерные степени
  и слишком большие числа отклоняются.
- Источник inline учитывается в `/users`, `/stats` и служебном журнале, без
  выдуманного ID чата назначения. Кэшированные ответы не добавляют повторных
  AI-счётчиков. Новых таблиц или зависимостей для обновления не требуется.

### Версия 1.12.1

- Расширен Circuit Breaker AI-маршрутов: существующая пауза квоты `429/402`
  дополнена карантином после `503`, прочих временных `5xx`, таймаутов и сетевых
  ошибок. Следующие сообщения сразу используют доступный резерв без повторного
  вызова остывающей модели. Карантин действует для пары «провайдер + модель».
- Заголовок `Retry-After` имеет приоритет над настройками: поддержаны секунды и
  HTTP-дата согласно [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after).
  При отсутствующем/невалидном заголовке пауза квоты остаётся 600 секунд
  (`AI_FALLBACK_COOLDOWN_SECONDS`), а временного сбоя — 60 секунд
  (`AI_TRANSIENT_COOLDOWN_SECONDS`). Обе величины можно изменить в `.env`.
- При `429/503` или сетевом сбое нет внутренних повторов перед переходом на
  резерв. Ожидание `Retry-After` не удерживает обработчик или очередь: маршрут
  просто пропускается. Прочие временные ошибки без заголовка сохраняют прежние
  ограниченные повторы, а затем тоже отправляют маршрут в карантин.
- Карантин повторно проверяется после ожидания слота AI/медиа. После окончания
  паузы только один пользовательский запрос проверяет восстановление маршрута;
  остальные пока используют резерв. Успех снимает карантин, повторный сбой
  открывает новую паузу, отмена запроса не оставляет зависшую проверку.
- Если все подходящие маршруты на паузе, бот сразу сообщает примерное время
  до ближайшей повторной проверки без пробных AI-генераций. `/diagnostics` показывает
  оставшуюся паузу и проверку восстановления. Пропущенные маршруты не добавляют
  фиктивных ошибок или AI-попыток в диагностику.
- Ошибка продолжения после частичного ответа также включает карантин, даже
  когда пользователю отправляется сохранённый фрагмент. Ошибки формата, доступа
  и фильтрация конкретного запроса не считаются сбоем всей модели.
- Всё состояние хранится только в ОЗУ и обнуляется при перезапуске. Новых таблиц
  SQLite или обязательных переменных окружения не требуется. Явный повторный
  выбор модели владельцем сохраняет прежнее поведение: сбрасывает её локальную
  паузу. Отключение автоперехода не отключает защиту от повторных вызовов, но
  запрещает переходить на резерв.

  обычных вопросов само по себе не считается нарушением.
- Журнал содержит до 1000 символов текста/подписи и тип вложения, а не файлы или
  ответы AI. Хранение — 30 дней, очистка при запуске и не чаще раза в час при
  обращениях. Не учитываются владельцы, Business и обычная беседа группы без
  обращения к боту. Старые сообщения задним числом не восстанавливаются.

  несвязанных сообщений.
- При reply бот передаёт текст и доступное вложение исходного сообщения вместе
  с новым вопросом.
- Отдельный контекст для личного чата, группы/темы или каждого пользователя —
  настраивается переменной `CONVERSATION_SCOPE`.
- Последовательная обработка одного диалога: два одновременных сообщения не
  перепутают цепочку запросов.
- Глобальное по Telegram ID ограничение частоты, защита от очереди запросов одного
  пользователя, временная блокировка спамеров, лимиты файлов и общего параллелизма.
- Повтор временных ошибок Gemini, понятные сообщения для 400/401/403/429/5xx и
  автоматический новый контекст, если сохранённая цепочка уже истекла.
- Автоматический переход на `generateContent`, если Interactions API недоступен
  в регионе хостинга.
- Обычный Markdown модели безопасно превращается в Telegram-оформление:
  заголовки, жирный и курсивный текст, ссылки, цитаты, списки и блоки кода.
- Ответы длиннее Telegram-лимита делятся с сохранением форматирования и точных
  UTF-16-смещений Telegram entities.
- На время запроса показывается анимированный статус обработки, который затем
  автоматически удаляется; стандартный индикатор «печатает…» также остаётся.
- При лимите любой выбранной модели временный статус показывает переход на
  следующую доступную модель и удаляется после готового ответа.
- Команды администратора группы и allowlist для закрытого бота.
- Учёт пользователей самого бота без сохранения текста их сообщений: имя,
  username, ID, время активности, источник и счётчики AI-запросов.
- Уведомление владельцу при первом обращении нового пользователя, а также
  владельческие отчёты `/users` и `/stats`.
- Локальная нарезка фотографии на бесшовную профильную стенку из 3–24 частей
  через `/wall`; API нейросетей для этого не используются.
- Мгновенные уведомления владельцу Telegram Business-аккаунта, если собеседник
  изменил или удалил сообщение; в уведомлении остаётся исходный текст.
- Одноразовое приветствие каждому Business-собеседнику перед первым AI-ответом:
  оно сообщает об автоответчике и доступных командах.
- Автоматическое сохранение входящих фото, видео, GIF, аудио, голосовых,
  кружков и документов: файл скачивается сразу и без уведомления, а владельцу
  отправляется только после удаления исходного сообщения.
- Секреты не записываются в исходники, SQLite и логи.

Важно: обычный Telegram-бот видит только личный чат с самим ботом и те
группы/каналы, куда его добавили. Он не получает произвольные личные переписки
вашего аккаунта. Для автоматических ответов в диалогах бизнес-аккаунта подключите
его как Telegram Business bot с правом чтения сообщений. Обработчики новых,
изменённых и удалённых Business-сообщений включены, а контекст каждой business
connection отделён от обычного чата.

## Стенка из фотографий

Функция работает в личном чате и не использует нейросеть:

1. Отправьте фотографию с подписью `/wall` или ответьте `/wall` на уже
   отправленное изображение.
2. Выберите 3, 6, 9 … 24 части. Можно сразу указать число: `/wall 9`.
3. Бот пришлёт превью и вертикальные JPEG-файлы 1080×1920 с номерами. Загружайте их строго
   от `01` к последнему номеру — обратный порядок нужен, чтобы новые элементы
   профиля сложились в исходную картинку.

Поддерживаются статичные JPEG, PNG и WEBP. Изображение автоматически
ориентируется по EXIF и кадрируется под сетку из трёх колонок. Исходный файл
ограничен 8 МиБ и 12 мегапикселями. В `.env` лимиты можно уменьшить; верхняя граница
12 Мп намеренно зафиксирована для Bothost с небольшим контейнером.

## Защита Telegram Business-переписки

1. В Telegram откройте **Настройки → Telegram Business → Чат-боты**.
2. Подключите созданного через BotFather бота и разрешите ему читать сообщения.
3. Откройте личный чат с ботом и нажмите **Start**, чтобы он мог присылать вам
   уведомления и сохранённые файлы.
4. Оставьте `BUSINESS_MONITOR_ENABLED=true` и `BUSINESS_ARCHIVE_MEDIA=true`.

Чтобы оставить только защитные функции без ответов собеседникам, отправьте боту
в личном чате `/autoreply off`. Команда отключает для владельца Business-аккаунта
ИИ-ответы, ответы на команды и приветствие, но не затрагивает снимки сообщений,
тихий архив медиа и уведомления об изменениях/удалениях. `/autoreply on` включает
ответы обратно, а `/autoreply status` показывает текущий режим. Выбор хранится в
SQLite и переживает перезапуск бота.

Для отдельных собеседников используйте `/chats` в личном чате с ботом. Бот
покажет последние 20 Business-диалогов с inline-кнопками: `✅` означает, что
автоответы включены, а `🔕` — что для этого собеседника работает только
мониторинг. Команды в переписку с собеседником отправлять не нужно. Общий
`/autoreply off` имеет приоритет и временно отключает ответы во всех чатах.

При новом входящем Business-сообщении бот сохраняет текстовый снимок в SQLite.
При `edited_business_message` он присылает версии «было/стало», а при
`deleted_business_messages` — удалённый текст. Поддерживаемое медиа скачивается
немедленно, но хранится без сообщений в локальном архиве. В личный чат владельца
оно загружается только после удаления оригинала, поэтому новые кружки и другие
файлы не дублируются. После успешной отправки архивная копия удаляется.

Telegram Bot API не сообщает значение таймера самоуничтожения для Business-медиа,
но помечает недоступное для сохранения сообщение признаком
`has_protected_content`. Чтобы явно сохранить такое таймерное фото или видео,
ответьте на него любым сообщением в диалоге с собеседником **до открытия**.
Вложение из ответа будет загружено в личный чат владельца с ботом. Обычные фото,
видео, кружки и медиа под визуальным спойлером при ответе игнорируются; ответы
самого бота и повторные ответы на уже сохранённое медиа тоже не создают копий.
Если Telegram не передал явный признак защищённого содержимого, бот не пытается
угадывать тип медиа и не создаёт дубликат. Обычный Bot API не имеет доступа к
секретным чатам; таймерные файлы из секретного чата сохранить таким способом
нельзя. Размер одной сохраняемой копии ограничен `BUSINESS_ARCHIVE_MAX_BYTES`, а
текстовые снимки и невостребованные файлы автоматически удаляются по истечении
`BUSINESS_MESSAGE_RETENTION_DAYS`.

Неподдерживаемые бинарные форматы (например, архив или исполняемый файл) не
отправляются Gemini. Бот передаёт модели только имя и MIME-тип и сообщает, что
содержимое недоступно. Анимированные TGS-стикеры также описываются текстом;
статические WebP и видео-стикеры WebM анализируются полностью.

## Быстрый запуск без Docker

1. Создайте бота через [@BotFather](https://t.me/BotFather), скопируйте токен.
2. Создайте ключ в [Google AI Studio](https://aistudio.google.com/app/apikey)
   либо в [OpenRouter](https://openrouter.ai/keys).
3. Установите Python 3.11 или новее и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

4. Откройте `.env` и выберите один из вариантов. Для прямого Google API:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
GEMINI_API_KEY=ключ_из_Google_AI_Studio
```

Для OpenRouter:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ключ_из_OpenRouter
OPENROUTER_MODEL=openrouter/free
```

5. Запустите:

```bash
python -m bot
```

Альтернативный запуск после `pip install .`:

```bash
gemini-telegram-bot
```

cp .env.example .env

База сохраняется в Docker volume `bot_data`. Контейнер работает от отдельного

## Развёртывание на bothost.ru

1. Отправьте проект в GitHub/GitLab и на странице создания бота Bothost укажите
   URL репозитория, ветку `main`, платформу Telegram и главный файл `main.py`.
2. Используйте стандартную Python-сборку Bothost (`requirements.txt` уже есть).
   Собственный `Dockerfile` также поддерживается, но для этого проекта не нужен.
3. Для OpenRouter добавьте `AI_PROVIDER=openrouter`, `OPENROUTER_API_KEY` и
   `OPENROUTER_MODEL=openrouter/free`. Для прямого Google API добавьте
   `GEMINI_API_KEY`; для ключа Vertex AI Express Mode (например, с префиксом
   `AQ.`) также установите `GEMINI_VERTEX_AI=true`. Если токен из формы
   создания не передаётся в контейнер, добавьте его как

Не загружайте `.env` в репозиторий: токены и API-ключи задаются только через
переменные окружения Bothost.

## Как работает маршрут через OpenRouter

Бот сначала получает Telegram update и скачивает поддерживаемое вложение в
оперативную память процесса. Затем он собирает единый запрос: текст остаётся
текстом, изображения и видео превращаются в Base64 data URL, аудио — в raw
Base64 с указанием формата, PDF — в Base64-файл. Запрос отправляется по HTTPS на
`https://openrouter.ai/api/v1/chat/completions` с ключом OpenRouter.

OpenRouter проверяет ключ и баланс, находит доступного поставщика выбранной
модели и передаёт ему запрос. Полученный текстовый ответ возвращается тем же
маршрутом в бот, после чего бот делит длинный текст по лимиту Telegram. VPN
пользователя в этой цепочке не участвует: сетевое соединение выполняет сервер
Bothost.

При `AI_PROVIDER=openrouter` ключ и оплата принадлежат OpenRouter, поэтому Google
Cloud-проект и его выбор страны не нужны. Содержимое запроса при этом видят как
OpenRouter, так и фактический поставщик модели. Для продолжения диалога бот
хранит в SQLite ограниченную текстовую историю и прикладывает её к следующему
запросу. По умолчанию это не более 6 обменов и 16 000 символов; содержимое
прошлых файлов повторно не сохраняется и не загружается. `/reset` удаляет
локальную историю текущего диалога. Текст и вложение сообщения, на которое
сделан Telegram reply, также входят в текущий запрос.

## Поведение в группах

Доступны три режима:

| Режим | Поведение |
| --- | --- |
| `mentions` | Ответ на `/ask`, `@username` бота или reply на сообщение бота |
| `all` | Ответ на каждое поддерживаемое сообщение |
| `off` | Автоматические ответы отключены, но `/ask` работает |

По умолчанию включён безопасный режим `mentions`. Администратор меняет режим
командой `/mode mentions`, `/mode all` или `/mode off`.

Чтобы режим `all` действительно видел обычные сообщения группы, отключите для
бота Group Privacy через `@BotFather` → `/mybots` → Bot Settings → Group Privacy.
Telegram с включённой приватностью отдаёт боту только команды, упоминания и
ответы, направленные ему. Telegram также не передаёт обычным ботам сообщения
других ботов, что защищает от бесконечных циклов.

В forum-группах каждая тема автоматически получает отдельный контекст. При
`CONVERSATION_SCOPE=chat_thread_user` контекст дополнительно разделяется по
авторам.

## Команды

| Команда | Назначение |
| --- | --- |
| `/start` | Краткое знакомство |
| `/help` | Возможности и режимы |
| `/menu` | Показать reply-клавиатуру в личном чате |
| `/hidekeyboard` | Скрыть reply-клавиатуру |
| `/inline` | Примеры перевода, исправления и калькулятора через @username |
| `/settings` | Панель управления с inline-кнопками; только владелец |
| `/diagnostics` | Ошибки, задержки и фактические AI-модели; только владелец |
| `/wall [3–24]` | Нарезать фотографию на бесшовную профильную стенку |
| `/ask текст` | Явный запрос; поддерживается и в подписи файла |
| `/reset` | Разорвать текущую цепочку контекста |
| `/cancel` | Остановить выполняющийся запрос |
| `/autoreply on\|off\|status` | Автоответы Telegram Business; только владелец |
| `/chats` | Индивидуальные режимы Business-собеседников |
| `/users [1–15]` | Последние пользователи самого бота; только ID из `OWNER_IDS` |
| `/ban ID` | Запретить доступ к боту; также ответом на сообщение, только владелец |
| `/unban ID` | Снять блокировку; также ответом на сообщение, только владелец |
| `/banlist` | Заблокированные пользователи с кнопками управления; только владелец в личке |
| `/stats` | Сводная статистика и расход AI-запросов; только ID из `OWNER_IDS` |
| `/model [provider] [model]` | Показать или сменить AI-провайдер/модель; только ID из `OWNER_IDS` |
| `/status` | Показать модель, режим и наличие контекста |
| `/mode ...` | Настроить группу; только администратор |

В группе `/reset` и `/cancel` доступны администраторам, потому что стандартный
контекст является общим для всей темы.

Для блокировки без копирования ID откройте `/users`, выберите человека и нажмите
«Заблокировать». В его карточке кнопка сменится на «Разблокировать». Список
пользователей и бан-лист открываются только владельцу в личке. Администратор
группы или владелец подключённого Business-аккаунта не получает этих прав
автоматически: нужен числовой ID в `OWNER_IDS`.

## Inline-режим в чужих чатах

Один раз включите режим у [BotFather](https://t.me/BotFather): отправьте
`/setinline`, выберите своего бота и задайте подсказку, например
`Запрос, tr en Текст, fix Текст или calc 2+2`.
[Документация Telegram](https://core.telegram.org/bots/api#inline-mode).
После обновления из Git бот уже получает `inline_query`; токен менять не нужно.

В поле ввода любого доступного вам чата или канала используйте свой username:

```text
@bot_username tr en Привет, как дела?
@bot_username исправь Превет, как дила?
@bot_username calc (15 + 5) * 3
@bot_username Что такое HTTP?
```

Сначала просмотрите результат в списке, затем нажмите на него для отправки.
У вас должны быть обычные права писать в выбранный чат/канал; inline не даёт
права публикации в чужом канале и не обходит ограничения Telegram на ботов.
В режиме перевода язык можно указать в запросе; без языка русский переводится
на английский, остальной текст — на русский. Калькулятор поддерживает
`+ - * / // % **`, `^` как степень, скобки, десятичную запятую и точку. Функций
и переменных в нём нет. Голое арифметическое выражение тоже распознаётся.

По умолчанию inline доступен всем незаблокированным пользователям. Для закрытого
режима задайте `INLINE_ALLOWED_USER_IDS=123456789,987654321`: владельцы из
`OWNER_IDS` также разрешены. Если задан `ALLOWED_CHAT_IDS`, а inline-список пуст,
разрешены только владельцы и пользователи, чей личный ID есть в старом списке.
Явный inline-список разрешает своим пользователям вызовы из любых доступных им
чатов; Telegram не сообщает боту ID чата назначения. Проверка банов выполняется
и перед выдачей результата из кэша. Уже загруженный клиентом или отправленный
inline-результат нельзя отозвать обычным баном.

AI-запросы стартуют после паузы при наборе. Начатый, а затем отменённый запрос
уже мог расходовать квоту провайдера — задержка и кэш уменьшают расход, но не
гарантируют бесплатность. Калькулятор вообще не обращается к AI. Перевод,
исправление и обычный вопрос отправляют введённый текст настроенному провайдеру;
посторонняя переписка, местоположение и история целевого чата не читаются.

не предоставляет доступ к этим отчётам.

## Контекст и приватность

Последние обмены при любом основном провайдере хранятся локально в SQLite с
жёсткими лимитами по числу и объёму, чтобы автоматическое переключение модели не
обрывало контекст. В Google-режиме дополнительно может использоваться серверная
цепочка Interactions API. Неактивная локальная история удаляется через 30 дней. Для
защиты Business-переписки SQLite дополнительно хранит исходный текст, имя
отправителя и тип вложения до 30 дней; сами файлы в SQLite не записываются, а
отправляются владельцу в Telegram. Токены и ключи в базу не записываются.
`/reset` удаляет локальную OpenRouter-историю или перестаёт использовать прежнюю
Google-цепочку, но не удаляет серверные журналы Google и снимки Business-сообщений.

Если настроено несколько API-ключей, при лимите или временной недоступности
выбранной модели бот по очереди пробует другие настроенные модели. Текст,
системная инструкция и ограниченная локальная история передаются новому
провайдеру. Groq принимает до трёх JPEG/PNG/WebP через `GROQ_VISION_MODEL`;
текстовые Groq-модели не получают двоичные вложения. Всю ротацию
можно отключить через `AI_AUTO_FALLBACK_ENABLED=false`, а участие Groq как
резерва — через `GROQ_FALLBACK_ENABLED=false`. Актуальные бесплатные лимиты
опубликованы в [официальной документации Groq](https://console.groq.com/docs/rate-limits).

Для отчётов `/users` и `/stats` SQLite хранит отдельную минимальную запись на
каждого пользователя самого бота: Telegram ID, имя, username, время первого и
последнего обращения, последний тип чата и числовые счётчики. Текст сообщений и
вложения в таблицу статистики не записываются. Собеседники подключённого
Telegram Business-аккаунта в эту статистику не входят и отображаются отдельно
через `/chats`. Такой учёт не создаёт дополнительных запросов к OpenRouter,
Groq или Google.

Отдельная таблица служебного журнала `user_activity` содержит время обращения,
Telegram ID пользователя, ID чата и сообщения, до 1000 символов текста/подписи,
тип события, результат и причину отказа. Самих вложений, ответов AI и содержимого
Business-переписки в ней нет. По умолчанию хранится не более 30 дней событий;
просроченные записи исключаются из истории сразу и удаляются при запуске и
периодически при новых обращениях. После перезапуска незавершённые события
отмечаются прерванными. Журнал не отправляется AI-провайдерам. `/reset` очищает
контекст модели, но не служебный журнал и не блокировки `user_bans`.

Обработанные inline-запросы попадают в тот же журнал с пометкой `[Inline]`,
в том числе когда пользователь лишь просмотрел результат и не отправил его
в чат. Промежуточные варианты, отменённые до генерации, не записываются.
Фиксируются также отказы общего AI-антиспама. Для неизвестных чата и сообщения
используется служебное значение `0`, которое не выдаётся за Telegram ID в отчёте.
AI-запросы учитываются как AI, локальные вычисления — как команды; попадание
в кэш повторно не увеличивает эти счётчики. Владельцы по-прежнему исключены.

Служебные команды не перечисляются в интерфейсе бота, но это не механизм
авторизации: права проверяются на сервере по `OWNER_IDS` при каждом запросе.
Исходный код публичного репозитория не является секретным. Перед использованием
журнала сообщите пользователям о хранении обращений и ограничьте доступ к файлу
базы и его резервным копиям.

По актуальной документации Gemini срок хранения Interaction по умолчанию — до
55 дней на платном уровне и 1 день на бесплатном. Настройки хранения и ручное
удаление доступны в Google AI Studio. Если требуется одноразовая обработка без
серверной истории, установите:

```dotenv
GEMINI_STORE_INTERACTIONS=false
```

В этом режиме каждое обращение независимо; reply-контекст текущего Telegram-
сообщения всё равно передаётся. Любое анализируемое содержимое отправляется
выбранному AI-провайдеру. В режиме OpenRouter оно проходит через OpenRouter к
фактическому поставщику модели. Перед добавлением бота в рабочий чат следует
уведомить участников и проверить применимые правила обработки данных.

Храните `.env` только на сервере. Если токен или ключ попал в публичный репозиторий,
немедленно перевыпустите его в BotFather/AI Studio, а не просто удаляйте строку из
последнего коммита.

## Формулы и LaTeX

Для ответов с формулами бот использует [нативные Rich Messages Telegram](https://core.telegram.org/bots/api#rich-message-formatting-options):
inline-математика передаётся в `tg-math`, отдельные уравнения — в `tg-math-block`.
Нужны Bot API 10.1+ и клиент Telegram с поддержкой Rich Messages. При использовании
старого локального Bot API, ограничений Business или отклонённого выражения бот
переходит на обычный текст с символами `π`, `½`, `√`, `ℤ` и записью дробей через `/`.
Для старого клиента можно явно установить `MATH_RENDER_MODE=text` на хостинге
и перезапустить бота: сервер не сообщает, умеет ли конкретный клиент показать формулы.

Пример разметки, которую бот преобразует в математический блок:

```latex
$$
\sin\left(\frac{2x}{3}\right)=\frac{1}{2}
$$

$$
\begin{aligned}
x &= \frac{\pi}{4}+3\pi n \\
\text{или}\quad x &= \frac{5\pi}{4}+3\pi n,\quad n\in\mathbb{Z}
\end{aligned}
$$
```

Это оформление исходного ответа модели, не независимая проверка решения.
Поддерживаются математические команды Telegram, а не произвольные TeX-документы
с пакетами и исполняемыми макросами. Текстовый запасной вариант ограничен
возможностями LaTeX-to-Unicode; сложная неподдержанная запись может остаться текстом.

Rich-ответы автоматически делятся по лимитам Telegram: 32768 байт UTF-8 и 500
верхнеуровневых блоков на сообщение. `REPLY_CHUNK_SIZE` по-прежнему применяется
к обычным ответам и текстовому fallback. При частичном отказе отправки fallback
строится только для ещё не доставленных Rich-блоков. Ответы с Markdown-картинками
остаются в текстовом режиме: поддержка формул не добавляет загрузку внешних медиа.
Переписка в SQLite хранится в прежнем исходном виде, без изображений и копий Rich HTML.
Новых переменных, кроме необязательного режима отображения, и миграций базы нет.

## Постоянная диагностика моделей

Команда владельца `/diagnostics` показывает исторические показатели за «24 часа»,
«7 дней» или «30 дней» и отдельно — текущее состояние маршрутов после запуска.
Кнопки выбора периода, обновления и перехода между страницами не расходуют
AI-квоту. Кнопка обновления каталога запрашивает только метаданные моделей.

Агрегаты записываются в `data/bot.sqlite3`, таблица `model_diagnostics` создаётся
автоматически при обновлении. Существующие настройки, баны, контексты и история
не удаляются. Новые секреты или пакеты не требуются. На хостинге должен сохраняться
тот же файл базы; удаление контейнера вместе с данными удалит и эту статистику.
Метрики из ОЗУ старых версий задним числом восстановить нельзя: сбор начинается
с первой попытки после обновления.

Единица учёта — завершённая логическая попытка одного AI-маршрута, а не сообщение
пользователя. Например, ошибка Google и успешный резерв Groq — две попытки.
Пропуск маршрута на карантине не считается новой ошибкой. Внутренняя ротация
ключей, сетевые повторы и автопродолжения относятся к той же попытке маршрута.
Частичный ответ считается успехом с отдельным счётчиком частичных ответов — это
не гарантия полноты или качества ответа. Калькулятор и другие локальные команды
AI-показатели не увеличивают; обычные и inline AI-запросы учитываются одинаково.

Среднее время вычисляется как сумма длительностей / число попыток, включая ошибки
и ожидание слота маршрута. Это не полное время обработки Telegram-сообщения.
Доля успехов — отношение успешных попыток ко всем попыткам, а не оценка uptime
провайдера. Для динамического `openrouter/free` сохраняется ID маршрута, а не
раздельная статистика всех моделей, которые шлюз выбрал внутри него.

Периоды состоят из 24/168/720 часовых бакетов UTC, включая текущий неполный час.
Начало периода выровнено по часу и отображается в панели: это почасовой отчёт,
а не точное скользящее окно до секунды. Хранятся число попыток, успехов, ошибок,
частичных ответов, сумма времени и время последней попытки для пары провайдер/модель.
Состояние Circuit Breaker и пулов ключей из этих агрегатов не восстанавливается.

## Пул API-ключей

В секретах окружения Bothost можно задать список вместо одиночного ключа:

```dotenv
GOOGLE_API_KEYS=your_google_key_1,your_google_key_2,your_google_key_3
GROQ_API_KEYS=your_groq_key_1,your_groq_key_2
```

Указывайте только собственные или явно предоставленные вам ключи. Непустой
`GOOGLE_API_KEYS` имеет приоритет над `GEMINI_API_KEYS`, затем используется старый
`GEMINI_API_KEY`. Для Groq непустой `GROQ_API_KEYS` заменяет `GROQ_API_KEY`.
Пустые списки не отключают старые переменные. После изменения нужен перезапуск.
Не отправляйте реальные значения ключей в чат, коммит или скриншоты панели.

Это отказоустойчивость, а не умножение бесплатной квоты: у Google лимиты
установлены [на проект, не на ключ](https://ai.google.dev/gemini-api/docs/rate-limits),
у Groq — [на организацию](https://console.groq.com/docs/rate-limits).
Несколько ключей одной квоты будут исчерпывать общий лимит. Пул не создаёт новые
квоты и не отменяет правила провайдера; для большей нагрузки используйте
разрешённые квоты и официальный запрос повышения лимитов/подходящий тариф.

Например, `429` на Google-ключе №1 вызывает попытку той же модели с ключом №2;
если все ключи вернули `429`, выбирается обычный резерв. Ключи на паузе не
проверяются заново до истечения своего срока. Выбор модели через `/model`
не снимает индивидуальный карантин ключей; перезапуск сбрасывает состояние ОЗУ.
Параллельные запросы, уже отправленные до первого `429`, всё ещё могут вернуть
тот же отказ — отозвать сетевую попытку задним числом нельзя.

Ротация внутри выбранного провайдера работает и при
`AI_AUTO_FALLBACK_ENABLED=false`, но переход на другие модели/API при этом запрещён.
В `/diagnostics` отображается число ключей без действующей паузы, а не обещание
доступности или бесплатности. Счётчики маршрутов относятся к логическим попыткам
модели: успешный ответ после внутренней смены ключа не считается ошибкой маршрута.
В inline-режиме сохраняется общий лимит ожидания — медленный перебор может не
успеть за 7 секунд. Пул не расширяет ни этот лимит, ни ограничения антиспама.

Для Google-пула локальная память ограничена `OPENROUTER_HISTORY_TURNS`,
`OPENROUTER_HISTORY_MAX_CHARS` и сроком хранения той же истории SQLite. При
`OPENROUTER_HISTORY_TURNS=0` старые реплики в Google-пул не передаются.
`GEMINI_STORE_INTERACTIONS` не включает общую серверную цепочку между ключами:
пул Google использует stateless `generateContent`; `/reset` очищает локальный
контекст как раньше. Самих ключей в базе нет. Клиенты SDK занимают немного
дополнительной памяти; это не создание процессов или отдельных копий медиа.

## Ограничения и масштабирование

- Проект использует long polling. Telegram не разрешает одновременно получать
  updates через webhook и polling; при старте код удаляет старую webhook-
  конфигурацию.
- SQLite и локальные блокировки рассчитаны на один экземпляр процесса. Для
  нескольких реплик потребуется общий PostgreSQL/Redis, распределённые блокировки
  и webhook-доставка с идемпотентностью updates.
- Максимальный размер намеренно установлен ниже лимитов Gemini и Telegram, чтобы
  base64-запросы не занимали слишком много памяти. Увеличивайте его только вместе
  с лимитами RAM и таймаутами.
- Модели имеют жизненный цикл. При прекращении поддержки достаточно заменить
  `GEMINI_MODEL` или `OPENROUTER_MODEL`, не меняя обработчики Telegram.

## Проверка проекта

Полная локальная проверка не обращается к Telegram, Gemini или OpenRouter:

```bash
pytest -q
python -m compileall -q bot tests main.py
ruff check .
```

Перед проверкой установите dev-группу, если она ещё не установлена:

```bash
pip install -e '.[dev]'
```

Реальный end-to-end тест требует собственных ключей: отправьте боту текст,
фото с подписью, reply на фото, голосовое, PDF и альбом; затем проверьте режимы
группы и `/reset`.
